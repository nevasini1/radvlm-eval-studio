# Training Experiment — RadDPO-Lite

> Research/demonstration prototype only. Not a medical device. Not for clinical use.
> Synthetic data only.

## What RadDPO-Lite is

RadDPO-Lite is a small, Apple-Silicon-friendly **text-side** training experiment bolted
onto RadVLM Eval Studio. It uses the existing evaluator (rule-based weak labeler + clinical
error taxonomy) to **generate clinically meaningful flawed/corrected report pairs**, then
trains a tiny **LoRA adapter** to *repair* flawed AI draft reports.

It is **not** a diagnostic image model. The trainable target is **report repair**:
rewriting a draft so it stops missing findings, hallucinating findings, flipping negations,
mixing up laterality, or mis-stating certainty.

> **Honest framing:** "Evaluator-generated clinical preference tuning for radiology draft
> repair." Not a new training algorithm — a portfolio-appropriate application of LoRA/QLoRA
> (SFT) with an optional DPO preference path, where the *novel work is the clinical
> preference-pair generation driven by your own evaluator.*

## Why it is GPU-light

- **LoRA / QLoRA** freeze the base model and train small low-rank matrices, so memory and
  compute stay tiny (LoRA, Hu et al. 2021; QLoRA, Dettmers et al. 2023).
- The base model is a **4-bit ~1 GB** MLX model (`mlx-community/Qwen3-1.7B-4bit`), realistic
  for a 16 GB MacBook with no CUDA.
- Apple **MLX `mlx-lm`** supports LoRA/QLoRA fine-tuning directly; quantized models trigger
  QLoRA-style training.
- We train on **text** (reports), not images — avoiding fragile, slow VLM fine-tuning.

## Why it is not a diagnostic model

- It never sees pixels for a clinical decision; it repairs *text* given labels + evaluator
  errors.
- Training data is **synthetic** and the labels come from a transparent rule-based labeler.
- Every output carries "AI draft — requires radiologist review" and a non-diagnostic
  disclaimer.

## How evaluator-generated preference pairs work

For each synthetic study:

1. Build a canonical **correct** report from the reference labels (capturing laterality and
   severity from the reference text).
2. Inject **one clinically meaningful error** (`error_augmenter`): missed / hallucinated /
   negation / laterality / uncertainty / severity / support-device.
3. Run the existing **evaluator** (`compare_reports`) on the flawed draft to detect the
   error(s).
4. Emit:
   - **SFT example** — chat messages: `system` (repair instructions) → `user` (indication,
     labels, similar cases, flawed draft, *evaluator-detected errors*) → `assistant`
     (corrected structured report with "Changes made").
   - **Preference example** — `{prompt, chosen=corrected, rejected=flawed}` for DPO.

The corrected ("chosen") report is the canonical correct report; the flawed draft is the
"rejected". This is exactly the chosen/rejected structure DPO consumes (Rafailov et al.
2023), and it is inspired by radiology-specific preference work such as DPO for suppressing
hallucinated prior-exam content and RRG-DPO (MICCAI 2025) — but here the preferences are
**generated by your evaluator**, not hand-labeled.

## How to run

```bash
# 0) prerequisites (demo data + index)
python scripts/make_demo_data.py
python scripts/build_index.py --dataset demo --embedding-backend fallback

# 1) generate evaluator-derived SFT + DPO pairs (synthetic)
python scripts/make_training_pairs.py            # writes outputs/training/{rad_repair_sft,rad_repair_dpo}

# 2) show the LoRA command without running it (works everywhere)
python scripts/train_report_repair_adapter.py --dry-run

# 2b) actually train (Apple Silicon only):
#     pip install "mlx-lm[train]"
python scripts/train_report_repair_adapter.py --iters 300

# 3) evaluate report repair before vs after (template fallback if no adapter)
python scripts/evaluate_report_repair_adapter.py
```

The Streamlit **Training Lab** tab wraps steps 1–3 (it only *dry-runs* training; long
training stays on the CLI).

## How to interpret results

`evaluate_report_repair_adapter.py` writes `outputs/training/eval_results.json` and
`eval_cases.csv`, reporting **before vs after** repair:

- missed / hallucinated / negation / laterality error counts,
- total high-severity errors,
- mean positive-label **F1**,
- **new errors introduced** by the repair.

### Real results — a LoRA adapter actually trained on a 16 GB Mac

This was trained for real on Apple Silicon (16 GB, no CUDA): `Qwen3-1.7B-4bit`, LoRA SFT,
300 iterations, batch size 1, lr 1e-5, ~97 synthetic training examples. **Train loss
3.45 → 0.03, validation loss 5.32 → 0.09**, peak memory **2.3 GB**, ~6 minutes, ~19 MB
adapter. Inference applies the model's chat template (the adapter was trained on chat turns)
plus a repetition penalty.

Before/after clinical errors over the 36 synthetic studies (all numbers are real, produced
by `evaluate_report_repair_adapter.py` — none fabricated):

| Metric | Flawed (before) | **Trained adapter** | Template fallback |
|---|---|---|---|
| Total clinical errors | 48 | **11** | 3 |
| High-severity errors | 25 | **5** | 0 |
| Missed findings | 9 | **0** | 0 |
| Hallucinated findings | 19 | **3** | 3 |
| Negation errors | 5 | **0** | 0 |
| Laterality mismatches | 8 | **5** | 0 |
| Mean positive-label F1 | 0.53 | **0.92** | 0.92 |
| New errors introduced | — | **7** | 2 |

Reading this honestly:

- The **trained adapter genuinely repairs reports** via real model inference — e.g. it
  rewrites a flawed *"No pneumothorax"* into *"Moderate right pneumothorax is present"* and
  drives missed findings and negation errors to **zero**, lifting label F1 **0.53 → 0.92**
  while cutting total errors **48 → 11**.
- It still introduces some new errors (**7**) and leaves a few **laterality** mismatches —
  expected for a ~1.7 B model trained on ~100 synthetic examples for 300 steps. More/real
  data and iterations would close the gap.
- The **template fallback** (used automatically when no adapter is present) rebuilds the
  report directly from reference labels and is an honest upper-bound baseline — not a
  deployable model.

> Results are labelled **"trained MLX adapter"** when an adapter is loaded, and **"template
> fallback (rule-based, not a trained model)"** otherwise. Adapter weights are **never
> committed** (`.gitignore` blocks `*.safetensors` and `outputs/*`).

## Limitations

- **Synthetic data only** by default — these are not clinical results.
- The **rule-based evaluator can be wrong** (misses paraphrases, complex negation), so the
  generated preferences inherit its blind spots.
- The **template fallback uses reference labels**; it is a baseline, not a deployable model.
- A small adapter is **not clinically validated** and is **not** a replacement for
  radiologist review.
- DPO training itself is an optional integration point; this build exports DPO-ready data
  and trains the SFT adapter.
